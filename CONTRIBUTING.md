# Contributing to PeeStream for WordPress & DooPlay

Thank you for helping improve the PeeStream ecosystem.

## Before opening an issue

- Search [existing issues](https://github.com/PeeStream/peestream-wp-dooplay/issues) for duplicates.
- Confirm whether you used the staging-only beta or an earlier release.
- Record the WordPress, DooPlay (if used), PHP, and database versions.
- Share concise reproduction steps and sanitized error messages. Never include access tokens, credentials, or personal data.

## Pull requests

1. Open an issue describing the intended change before substantial work.
2. Keep changes narrowly scoped and document any changes to database schema or post metadata.
3. Add or update automated tests and explicitly identify mocked behavior.
4. Do not label a simulation as a live CMS end-to-end test.
5. Do not enable automatic migrations, post publishing, or external uploads without explicit administrator opt-in.

Public documentation, issue templates, and pull request descriptions must be in professional English. Do not commit production configuration or credentials.
